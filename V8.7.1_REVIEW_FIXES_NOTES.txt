V8.7.1 — v8.7.0 리뷰 후 버그 수정 (기능 추가 없음)

[수정한 버그]
1. percentileRank 범위 오류: 값이 직전 60개월 최대를 넘으면 순위가 1.09~1.5가 되고, "낮을수록 좋은" 지표(달러·Fed·BTC.D)는 음수가 되어
   구성요소 점수가 만점 초과(예 11/10) 또는 마이너스(-2/20)가 됨. 합성 데이터 기준 1246회 중 63회(5%) 발생, 신고점 구간에 집중.
   → mid-rank 백분위(항상 0~1)로 교체. 수정 후 0회.
2. 새로고침(10분 자동/버튼)마다 "우호적/부정적" 줄이 계속 누적되던 문제 (innerHTML 이어붙임).
3. 게이지 색 구간이 25%씩 고정이라 실제 보정 밴드(예 46/56/65)와 불일치, 눈금 라벨이 겹침 → 밴드 값대로 폭/위치 계산.
4. M2 발표지연(1개월 lag)이 달러·Fed·S&P·10Y 에도 적용되어 현재 점수가 한 달 묵은 값으로 계산됨 → lag 는 M2 에만 적용.
5. 현재 월 BTC 90일 수익률이 월말 기준이라 월초엔 약 65일 창으로 계산됨 → 현재 월은 정확히 90일 창.
6. Fed/달러/S&P "현재값"이 FRED 월평균 집계값인데 라벨이 없어 실제 종가처럼 보임 → "(월평균)" 표기.
7. Mayer 히스토리가 600일로 줄어 장기 위치 맥락이 사라짐 → 12페이지(약 6.5년)로 복원 (KV 캐시 6시간이라 비용은 드묾).

[수정하지 않은 설계 이슈 — 판단 필요]
A. 2017 알트장 구간 점수 누락: ETH/BTC(Coinbase) 자료가 2016-05 시작 + 백분위 최소 표본 12개월 → 전체 점수가 2017-08 부터.
   2017-03~07(ETH/BTC 급등기)이 비어 "2017 시작월 점수 —", 최초 돌파가 '시작 5개월 후'로 보임 (신호가 아니라 데이터 커버리지 때문).
B. 과거 '알트 확산 15점'이 BTC.D·ETH/BTC·스테이블 백분위 평균 proxy → BTC.D(20)·ETH/BTC(10)와 이중 계산되어 과거 실효 가중치는 BTC.D 약 25, ETH/BTC 약 15.
   현재 점수는 실제 breadth 를 쓰므로 구성이 다름. 알트 강세 구간 자체가 'BTC.D↓·ETH/BTC↑'로 정의되므로 적중률이 부풀려질 수 있음.
C. Watch/Expansion/Broad 밴드는 과거 점수 분포의 60/78/90 분위수(전체 표본 in-sample)라 "Broad = 역대 상위 10%"가 정의상 성립.
   '몇 점부터 알트장이 시작됐나'의 객관적 답이 아니라 '역대 상위 몇 %인가'에 가까움 — 보정표(적중/오탐/최초 돌파)를 함께 볼 것.
D. 각 지표를 60개월 백분위로 바꾸면 절대 수준 정보가 사라짐 (예: Fed 0% vs 5%).
E. 과거 BTC.D 는 CMC 실측 실패 시 연평균 앵커 보간(근사).
F. 실제 외부 API 응답으로는 검증 못 함 (합성 mock 으로만 검증). FRED 월평균 옵션(fq=Monthly&fam=avg)은 브라우저에서
   https://fred.stlouisfed.org/graph/fredgraph.csv?id=DTWEXBGS&cosd=2010-06-01&fq=Monthly&fam=avg 를 열어 월별 행이 나오는지 확인 권장.
